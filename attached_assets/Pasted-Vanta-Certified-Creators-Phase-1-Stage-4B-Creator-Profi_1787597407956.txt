Vanta Certified Creators — Phase 1, Stage 4B: Creator Profile Frontend ONLY
Continue in Free Mode. Do not switch to Power.
The Creator backend foundation is complete and working:
GET /api/creator/me
POST /api/creator
PATCH /api/creator
GET /api/creators/:username
Admin certification API already exists
Do not modify Creator database schema or backend APIs during this stage unless a verified frontend-blocking contract bug exists.
Do not modify Passport, XP, achievements, Rooms backend/environments, Marketplace backend, Vanta Play, Transmission, Vault, Releases, World, authentication architecture, startup, or unrelated systems.

Give every Vanta Member the ability to create/edit a public Creator Profile, and give every Creator a public profile page that becomes their creative identity inside Vanta.

4. Profile imagery
The backend contains profile/banner image fields, but do NOT create a new insecure Member upload system during this stage.
Inspect whether a safe existing Member-authorized image upload mechanism already exists.
If not, use a polished default Vanta avatar/banner treatment for now and leave image uploading for a separate stage.
Do not open the Admin-only generic upload endpoint to Members.
Do not use base64 profile images.
5. Visual direction
Creator Profiles should feel like a creative identity card / artist page inside Vanta OS, not LinkedIn and not Fiverr.
Think:
underground artist profile
editorial
music/fashion/media culture
Y2K digital identity
dark Vanta interface
The Certified Creator badge should be visually distinctive but restrained.
Keep mobile responsive.
6. Authentication behavior
/creator
requires sign-in.
Guests should be routed to the existing login flow.
/creators/:username
is public.
Use the existing useUser() / getUserToken() system.
Do not refactor authentication.
7. Navigation
Do NOT add Creator to the Vanta OS launcher yet.
Do not change global navigation during this stage.
We will decide later whether Creator belongs in the launcher, Passport, or both.
