Core concept
Creator Work is the public portfolio attached to a real Vanta Creator Profile.
It should allow creators to show what they have actually made across music, fashion, photography, media, development and other creative fields.
Work belongs to a Creator Profile / authenticated Member identity.
Database
Add one minimal additive table such as:
creator_work_items
Suggested fields:
id UUID primary key
creator_user_id reference to existing user
title
description nullable
work_type
external_url nullable
thumbnail_url nullable
room_id nullable
sort_order default 0
is_featured default false
created_at
updated_at
Do not duplicate Creator Profile information.
Use creator_user_id to connect Work to the existing Creator identity.
If room_id is used, reference the existing Rooms table without modifying Rooms.

Do not build a category-management system.
Important upload rule
Do NOT build Member file uploads during this stage.
Vanta's current generic upload endpoint is Admin-oriented and we have not yet built a dedicated safe Member media-storage layer.
Phase 1 Creator Work should therefore support external/public URLs and metadata only.
Do not use base64.
Do not open Admin upload permissions to Members.
A later stage will handle Creator media uploads properly.
Member APIs
Add isolated Creator Work routes.
Prefer a dedicated module such as:
server/creator-work-routes.ts
Create Work item
POST /api/creator/work
Authenticated Member only.
Requirements:
Member must already have a Creator Profile.
derive creator identity from currentUser
never trust creator_user_id from the browser
validate title/type/URLs
Update own Work item
PATCH /api/creator/work/:id
Creator may only edit their own item.
Delete Work item
DELETE /api/creator/work/:id
Creator may only delete their own Work item.
For Phase 1, hard deletion is acceptable unless the project already has a clear soft-delete convention.
Own Work
GET /api/creator/work
Authenticated Member only.
Return their own Work items.
Public Creator Work
Extend the existing public Creator response cleanly OR add:
GET /api/creators/:username/work
Prefer whichever keeps Creator routes cleaner.
Return only public-safe Work data.
Order featured items first, then sort_order, then newest.
Do not expose internal user fields.
Optional Room association
A Creator may optionally associate Work with a public Room they belong to.
If room_id is supplied:
Room must exist
Room must be public
Creator must currently belong to that Room
Do not modify Room tables or Room UI yet.
Featured Work
Allow Creators to mark a small number of items as featured.
For Phase 1, enforce a maximum of 3 featured Work items per Creator.
Do this server-side.
Security
A Creator must never:
edit another Creator's Work
delete another Creator's Work
create Work for another user
associate Work with a Room they have not joined
Existing suspended-Member enforcement through requireUser should automatically apply.
Do not add separate suspension checks.
