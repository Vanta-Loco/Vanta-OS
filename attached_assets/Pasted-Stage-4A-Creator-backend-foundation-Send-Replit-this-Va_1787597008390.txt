This task is ONLY the backend/database foundation for Creator Profiles + Certified Creator status.

Core concept
Every authenticated Vanta Member may create a Creator Profile.
A Creator Profile represents their public creative identity across Vanta.
Certified Creator is a separate Vanta-approved status.
Members must NEVER be able to certify themselves.
Certification should initially be controlled through the existing Admin system.
Creator Profile data
Add the minimum additive database structure needed for one Creator Profile per real Vanta user.
Suggested fields:
id — UUID
user_id — unique reference to existing user
display_name
bio
city — nullable
country — nullable
profile_image_url — nullable
banner_image_url — nullable
creator_type / primary discipline
disciplines
instagram_url — nullable
website_url — nullable
spotify_url — nullable
soundcloud_url — nullable
is_certified — default false
certified_at — nullable
created_at
updated_at
Keep this additive and minimal.
Do not duplicate Passport identity fields unnecessarily.
user_id is the connection between Passport identity and Creator identity.

Certification
is_certified must NEVER be writable through normal Member profile APIs.
A Member cannot:
set themselves certified
change certified_at
impersonate another Creator
Certification should only be changed through an authenticated existing Admin route/action.
Reuse the current Admin architecture.
Do not create a second Admin authentication system.
Public APIs
Add isolated Creator API routes.
Prefer a dedicated file such as:
server/creator-routes.ts
Public creator profile
GET /api/creators/:username
Return safe public data:
username
display name
bio
location where supplied
profile/banner images
disciplines
public social links
Certified Creator status
created date where appropriate
Do not expose email, password data, tokens or private Member information.
Current Member creator profile
GET /api/creator/me
Authenticated Member only.
Return their own creator-profile state.
Create creator profile
POST /api/creator
Authenticated Member only.
Derive user_id from currentUser.
Never accept a browser-supplied user_id.
Only one Creator Profile may exist per Member.
Update own creator profile
PATCH /api/creator
Authenticated Member only.
Member may update their allowed public fields.
They MUST NOT be able to update:
user_id
is_certified
certified_at
Marketplace connection

A Creator's Marketplace listings can already be found through the existing listing creator_user_id.
Architect the Creator API so the future profile page can retrieve/display that Creator's active Marketplace listings without changing Marketplace ownership.
If an additional filtered Marketplace query is already supported cleanly, reuse it.
Do not duplicate Marketplace listings into Creator tables.
Rooms connection

Creator Room membership should continue to come from the existing room_memberships table.
Do not duplicate memberships into Creator Profiles.

Admin certification API
Use the existing Admin authentication system to add the smallest necessary certification action.
For example:
PATCH /api/admin/creators/:id/certification
Body:
{ "certified": true }
or false.
Only authenticated Admin may perform this.
When certified:
set is_certified = true
set certified_at
When certification is removed:
set is_certified = false
clear or appropriately update certification timestamp
