PHASE 1.1 — MAKE VANTA DEPTH VISIBLY WORK ON MOBILE

The Phase 1 depth/parallax system is implemented correctly from a technical standpoint, but on an actual iPhone the visual difference is currently too subtle to notice.

Do not add Phase 2 features yet.

First inspect the existing VantaDepth, ParallaxLayer, AtmosphericOverlay, responsive CSS/media queries, and scroll-progress implementation and determine exactly why the motion is barely perceptible on mobile.

PRIMARY GOAL

Keep the existing Vanta design and navigation exactly as they are, but make the depth effect clearly visible on a real phone while scrolling.

It should still be tasteful and cinematic, but I should immediately be able to tell:

“the environment is moving independently from the webpage.”

⸻

1. DO NOT OVER-REDUCE MOBILE MOTION

Mobile should have slightly less motion than desktop, but it should NOT become effectively static.

Review any mobile multipliers or media queries introduced in Phase 1.

Increase the mobile movement enough to be obvious.

As an approximate starting target:

HERO BACKGROUND
scale around 1.07–1.10 at entrance
→ gradually settle around 1.01–1.03

vertical parallax travel
approximately 30–60px across the hero scroll range

FOREGROUND / HERO CONTENT
approximately 10–25px of opposing or different-rate movement

ATMOSPHERE
visibly drifting, but slow

Tune these values based on the existing layout rather than blindly applying them.

⸻

2. MAKE THE DEPTH RELATIONSHIP OBVIOUS

Right now simply moving everything slightly in the same direction may be visually indistinguishable from normal scrolling.

Ensure there is a clear difference between layers.

For example:

BACKGROUND
moves slowest

ENVIRONMENT IMAGE
moves at a different rate

ATMOSPHERIC OVERLAY
slowly drifts independently

TEXT / UI
remains comparatively stable

The image and typography should feel separated in depth.
Do not make text difficult to read.
 
⸻
 
3. MAKE THE HOMEPAGE HERO THE SHOWCASE
Strengthen the current homepage hero first.
When I scroll on an iPhone I should visibly see:
* the Vanta environment move at a different rate from the page
* a subtle camera push/pull
* atmospheric movement
* the foreground interface remaining readable
This is our test area for the motion language.
Do not spread weak effects over every page just to say the system is implemented.
Make one excellent hero interaction first.
 
⸻
 
4. ATMOSPHERE NEEDS TO BE VISIBLE
The current atmospheric layer may be too faint.
Increase it carefully.
Use the existing Vanta aesthetic:
* dark haze
* subtle purple illumination
* soft moving light
* slight grain/scan texture
* very slow environmental drift
Do NOT add strong glitches yet.
Do NOT cover the existing render.
This should look like the render itself has come alive.
 
⸻
 
5. IMPROVE SECTION DEPTH
The transition from the hero into the next homepage section should have noticeable spatial separation.
Instead of the next section simply scrolling upward normally:
* allow the hero environment to remain visually present slightly longer
* let the next content layer travel over/through it
* gradually darken or mask the previous environment
Keep all text and buttons accessible.
This should produce a restrained version of the dimensional movement we liked from the Active Theory reference without copying their spiral.
 
⸻
 
6. CHECK 
prefers-reduced-motion
Preserve accessibility support.
Do not disable prefers-reduced-motion.
However, verify that normal iPhone users are not accidentally receiving the reduced-motion version because of an incorrect media query or implementation bug.
Report:
* what happens when reduced motion is OFF
* what happens when reduced motion is ON
If reduced motion is ON, keeping the page mostly static is correct.
 
⸻
 
7. TEST ACTUAL SCROLL VALUES
Do not judge the result only from screenshots.
Screenshots cannot properly demonstrate parallax.
During testing, verify that scroll progress actually changes the relevant transforms.
Report sample computed values at:


top of hero
25% hero scroll
50% hero scroll
75% hero scroll
bottom of hero

Show the resulting translate/scale values for the main background layer.
This confirms the animation is genuinely moving.
 
⸻
 
8. KEEP NAVIGATION UNTOUCHED
Do not modify:
* top navigation structure
* page routes
* page headings
* buttons
* existing copy
* existing images
* search
* account/navigation behaviour
Navigation should remain simple and predictable.
Experimental visuals, conventional navigation.
 
⸻
 
9. PERFORMANCE
Maintain:
* smooth iPhone scrolling
* no scroll locking
* no horizontal overflow
* no constant React rerenders
* requestAnimationFrame/CSS-variable architecture
* GPU-friendly transforms
Aim for visual impact through intelligent movement rather than adding heavy libraries.
 
⸻
 
SUCCESS TEST
On a normal iPhone with Reduce Motion disabled:
I should be able to slowly scroll the Vanta homepage and clearly see the existing Vanta render behaving like a dimensional environment rather than a static background image.
It should still look like the same Vanta website.
It should just feel alive.
After implementing, tell me:
1. Why Phase 1 was difficult to perceive on mobile.
2. What mobile motion values were changed.
3. What visibly moves now.
4. Whether prefers-reduced-motion is functioning correctly.
5. Which files changed.
Do not proceed to environmental states or glitches yet.
