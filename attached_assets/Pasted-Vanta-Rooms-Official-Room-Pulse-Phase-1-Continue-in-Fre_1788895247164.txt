This task is ONLY to add a compact ROOM PULSE overview for the four official Rooms using existing real Room data.
Do not create real-time presence, online counts, recommendations, likes, comments, or new social systems.
Goal
When someone enters an official Room, they should immediately understand:
what is happening there
who is part of the space
what has recently been made
what is available
where to go next
ROOM PULSE should feel like a live creative-space overview, not another dashboard.
1. Add ROOM PULSE
Add a compact section labeled:
ROOM PULSE
Place it naturally near the top of the official Room interface, before or alongside the existing tab content.
Do not replace:
Feed
Members
Work
Listings
Room Tools
ROOM PULSE is an overview of those systems.
2. Real Room stats
Use only real existing data.
Show compact metrics where available:
member count
Work count
active listing count
Example:
18 MEMBERS / 7 WORKS / 3 LISTINGS
Do not invent:
online counts
activity scores
popularity
trending percentages
3. Latest Work
Show the newest real Creator Work associated with the current Room.
Maximum:
1 featured/latest item prominently
optionally 1–2 additional compact items if already easy to load
Show:
title
Work type
Creator identity
thumbnail or existing Work placeholder
Action:
VIEW WORK
should activate/open the existing Work tab or existing public Work destination.
Do not duplicate Creator Work.
4. Latest Listing
Show the newest active Marketplace listing associated with the Room where available.
Include:
listing title
category
Creator
price/price type where available
Action:
VIEW LISTING
opens the existing Marketplace detail route.
If the Room has no listings, omit the block or show a restrained empty state.
5. Recent Feed signal
If the Room has Feed posts, show the latest real post as a small pulse item.
Include:
author public identity
short text preview
timestamp
Action:
OPEN FEED
activates the existing Feed tab.
Do not expose private data or build comments/reactions.
6. Creators in the space
If public-safe Creator identities are already available from current Room membership data, show a small:
CREATORS IN THIS SPACE
preview.
Maximum 3–4 Creator identities.
Prefer Members with active Creator Profiles.
Show:
display name or @username
discipline where available
Certified treatment where real
Clicking should open:
/creators/:username
Do not expose Members without Creator Profiles as “Creators.”
Do not build another Creator Directory inside the Room.
7. Room-specific emphasis
Keep the same core Pulse structure, but let each official Room emphasize its identity:
Music
Prioritize:
Music Work
music-related listings
Artists / Producers / Engineers
Fashion
Prioritize:
Fashion Work
fashion listings
Designers / Models / Stylists
Visual
Prioritize:
Photography / Video / Design Work
visual-service listings
Photographers / Filmmakers / Designers
Media
Prioritize:
Writing / Media Work
relevant listings
Writers / Journalist-Media / Curators
Do not hide real Room content merely because it falls outside the preferred discipline.
This is emphasis, not hard filtering.
8. Empty Room behavior
Official Rooms may be quiet early on.
Use intentional empty states instead of fake activity.
Examples:
NO WORK ON THE WALL YET
NO LISTINGS IN THIS SPACE
FEED IS QUIET
Joined Creators may receive existing links to:
Add Work
Post to Feed
create Marketplace listing
only where those actions already exist.
Do not build new creation flows.
9. Joined vs visitor
Public visitors may view public-safe Room Pulse information.
Joined Members should retain all existing Member functionality.
Do not change access-control rules.
Do not expose private Room information.
10. Visual direction
ROOM PULSE should feel integrated into the Room environment:
environmental HUD
studio status display
venue activity board
early-2000s system monitor
Avoid:
analytics dashboard
social media feed clone
big colorful KPI cards
Preserve the rendered Room background.
Use translucent/dark panels consistent with existing Room HUD.
11. Member-created Rooms
Do NOT apply the tailored ROOM PULSE to member-created Rooms during Phase 1.
Keep their current interface unchanged.
Official Rooms only.
12. Backend discipline
Reuse existing Room, Work, Listings, Feed, Member and Creator read data where possible.
If the current Room APIs do not expose the minimal data needed for Pulse, add only lightweight read-only fields/endpoints.
Do not:
change schema
duplicate data
create expensive aggregation systems
build real-time infrastructure
