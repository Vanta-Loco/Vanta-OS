Vanta OS — Activity Center Phase 1B: Member UI ONLY
Continue in Free Mode. Do not switch to Max/Power.
Activity Center Phase 1A backend is complete.
Existing endpoints:
GET /api/activity
GET /api/activity/unread-count
PATCH /api/activity/:id/read
POST /api/activity/read-all
This task is ONLY to build the Member-facing Activity Center UI.
Do not begin wiring Rooms, Passport, Creator, Marketplace, Play, or other systems to emit Activity events yet.
Do not modify database schema or Activity backend contracts unless a verified UI-blocking bug exists.
Goal
Add a global Vanta OS Activity interface that answers:
“What happened around my Vanta account?”
It should feel like part of the OS shell, not a social-media notification clone.
1. Global Activity action
Add an:
ACTIVITY
control to the authenticated Vanta OS header/shell.
Show a small unread count using:
GET /api/activity/unread-count
Examples:
ACTIVITY 3
or a restrained badge.
If unread count is zero, do not show a loud empty badge.
Keep Vanta Guide and existing navigation intact.
2. Activity drawer / overlay
Clicking Activity should open a compact OS-style drawer or panel.
Desktop:
side drawer or anchored system panel
Mobile:
near-full-screen panel
Do not navigate away from the current page just to inspect Activity.
3. Load real Activity
Use:
GET /api/activity
Display newest first.
Use only real backend data.
Do not create sample/fake notifications.
4. Activity item presentation
Each item should support:
event title
body where available
actor identity where available
timestamp
unread/read state
target link where available
Public actor identity may include:
@username
Creator display name
Certified Creator state
Do not expose private Member information.
5. Event-type treatment
Use subtle event labels/icons for known types such as:
Room
Passport
Creator
Work
Marketplace
Play
System
Do not make every event visually loud.
Avoid emoji-heavy presentation.
6. Mark one as read
If an unread Activity item is opened or intentionally selected, call:
PATCH /api/activity/:id/read
Update:
item read state
unread count
immediately after success.
Do not mark every Activity item as read merely by opening the drawer.
7. Mark all as read
Add a restrained:
MARK ALL READ
action using:
POST /api/activity/read-all
Hide or disable it when there is nothing unread.
Update UI immediately after success.
8. Target navigation
If target_url exists, provide a clear way to open it.
Examples later may route to:
Room
Creator Profile
Work
Marketplace
Play
Passport
Use existing Vanta routes.
If no target exists, the Activity item should still render normally.
9. Empty state
Since Phase 1C has not started yet, many Members may legitimately have no Activity.
Show:
NO ACTIVITY YET
Updates connected to your Vanta account will appear here.
Do not create fake events just to populate the panel.
10. Loading / error states
Add restrained Vanta-style states:
LOADING ACTIVITY...
safe error state
Do not expose raw backend errors or stack traces.
11. Refresh behavior
When the Activity panel opens:
refresh unread count
refresh Activity list
After marking items read, keep count and list synchronized.
Do not add aggressive polling during Phase 1B.
Real-time/WebSockets are not required.
12. Authentication
Use the existing Member token flow:
getUserToken()
X-User-Token
Suspended Member handling is already centralized in the backend.
Do not add new auth logic.
Guests should not see authenticated Activity content.
13. Visual direction
Activity Center should feel like:
Vanta OS system inbox
underground terminal activity log
console notification drawer
early-2000s digital interface
Avoid:
Instagram notification feed
Facebook
generic SaaS bell dropdown
Use existing Vanta:
typography
dark surfaces
subtle borders
compact metadata
CRT/Y2K influence
14. Mobile
Ensure:
panel fits viewport
no horizontal overflow
Activity rows remain easy to tap
close action remains accessible
long titles/bodies wrap correctly
15. Preserve
Do not modify:
Activity database schema
Activity event emitters
Dashboard
